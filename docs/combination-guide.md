# 智囊团组合指南

> 本文是**使用与创作手册**：怎么让多位专家一起论证一个问题，怎么新增一个组合，怎么新增一位专家。
> 组阁的完整算法（两级命中、排序键、情境补位）写在 [combos/ROUNDTABLE.md](../combos/ROUNDTABLE.md)，本文不重复，只给出可执行入口。

---

## 一、组合是什么

组合不是"把几个专家放进一个文件"，而是**一次性地按问题需要组一个席位有限、角色不重叠的圆桌**。它有三层固定结构：

| 层 | 回答的问题 | 人数上限 | 典型角色 |
|----|-----------|---------|---------|
| **① 宏观定调** | 现在是什么环境？哪些结构性变量在起作用？ | ≤3 | 高善文（中国宏观）、格林斯潘（全球宏观）、伯南克（货币政策） |
| **② 中观筛选** | 这个环境里，哪些方向值得看？哪里藏着偏误与泡沫？ | ≤2 | 芒格（逆向/偏误）、索罗斯（反身性）、佩雷斯（技术周期） |
| **③ 微观决策** | 具体标的能不能下手？买/不买/太难？ | ≤2 | 巴菲特（护城河/安全边际）、段永平（商业模式）、邱国鹭（估值） |

**顺序不能乱。** 宏观没定调就谈个股，等于在不知道水位的情况下讨论某块礁石的高度；微观先给结论再补宏观，等于让结论倒推环境。三层是一次论证的三个阶段，不是三个可任选的模块。

## 二、30 秒上手

不需要读任何文件，一条命令即可组阁（在仓库根目录执行）：

```bash
python tools/skill-gen/assemble.py "美联储降息对A股意味着什么"
```

真实输出（2026-10 实测，仓库 v2.7.0）：

```
问题：美联储降息对A股意味着什么
命中标签：美联储、A股 + 口语词：降息、美联储

正式席位：
  ① 宏观定调：ben-bernanke (BB) 本·伯南克  greenspan (GP) 格林斯潘  li-daxiao (LD) 李大霄
  ② 中观筛选：beijing-chaojia (BC) 北京炒家  xu-xiang (XX) 徐翔
  ③ 微观决策：warren-buffett (WB) 沃伦·巴菲特

列席备询：
  fu-peng (FP) 付鹏

建议数据清单：
  - 宽基指数行情与估值（沪深300/上证/创业板/科创50 PE）
  - 宏观与政策（LPR/社融/利率/汇率）
  - 指数估值分位（PE/PB 历史分位）
  - 市场情绪/资金流（北向、量能）
  - 候选个股行情与估值（PE/PB/股息）
  - 个股财务与财报质量
```

换一句口语化的问题，可以看到口语兜底词表在起作用：

```bash
python tools/skill-gen/assemble.py "当前A股能不能上车"
```

```

命中标签：A股 + 口语词：上车

正式席位：
  ① 宏观定调：li-daxiao (LD) 李大霄  gao-shanwen (GS) 高善文  hong-hao (HH) 洪灏
  ② 中观筛选：beijing-chaojia (BC) 北京炒家  xu-xiang (XX) 徐翔
  ③ 微观决策：duan-yongping (DY) 段永平  peter-lynch (PL) 彼得·林奇

  qiu-guolu (QG) 邱国鹭  warren-buffett (WB) 沃伦·巴菲特
```

需要程序化处理时加 `--json`，输出中的键一律是 **slug**（唯一主键），不是短代码：

```bash
python tools/skill-gen/assemble.py "当前的AI板块是不是泡沫" --json
```

```json
{
  "question": "当前的AI板块是不是泡沫",
  "hit_tags": ["泡沫"],
  "oral_words": ["泡沫", "ai"],
  "formal": ["george-soros", "robert-shiller", "greenspan", "carlota-perez", "gartner-hype-cycle", "warren-buffett"],
  "column": ["howard-marks"],
  "data_plan": ["宽基指数行情与估值（沪深300/上证/创业板/科创50 PE）", "..."]
}
```

**拿到席位之后才开始读 SKILL.md**——只读被选中的那几份。这是仓库的"低 token 原则"：不要为了组阁而把 51 份 SKILL.md 全量读一遍。

## 三、脚本组阁 vs 手写组合

两种方式并存，用途不同：

| 场景 | 用脚本 | 用手写组合文件 |
|------|-------|--------------|
| 一次性问题、临时提问 | ✅ | |
| 需要可复现、可审计的组阁结果 | ✅（确定性排序，同输入同输出） | |
| 需要沉淀一个反复使用的分析套路 | | ✅ |
| 需要固定输出格式、写作分工、交付物约定 | | ✅ |
| 问题跨域、标签体系覆盖不到 | | ✅（人工挑选，注明理由） |

**手写组合不是绕开算法，而是算法的上层。** 允许在主场上微调脚本给出的席位，但必须在文件里写明"为什么换人"——否则半年后没人知道当时为什么把索罗斯换成芒格。

现有手写实录示例（可直接当模板参考）：

- [`combos/examples/A股上车圆桌实录.md`](../combos/examples/A股上车圆桌实录.md)
- [`combos/examples/中美市场入场圆桌实录.md`](../combos/examples/中美市场入场圆桌实录.md)

## 四、读机器索引：`registry/roundtable-matrix.json`

脚本不解析 Markdown，只读这个文件。结构如下（字段均经实测）：

| 字段 | 类型 | 含义 |
|------|------|------|
| `version` / `updated` | string | 生成版本与日期，由 `build.py` 写入 |
| `alias_map` | object | slug → 2 字母短代码（仅展示用，**不是**主键） |
| `stages` | object | 三个阶段各自的成员 slug 列表（键为 `宏观定调` / `中观筛选` / `微观决策`） |
| `experts` | object | **slug 为键**，值为 `{code, person, role, tags, stage, path}` |
| `tag_index` | object | 标签 → 命中的 slug 列表，组阁路径 A 的数据源 |

每位专家的记录长这样：

```json
"gao-shanwen": {
  "code": "GS",
  "person": "高善文",
  "role": "中国宏观背景提供者",
  "tags": ["中国宏观", "资产定价", "房地产", "人口", "货币政策", "汇率"],
  "stage": "宏观定调",
  "path": "skills/gao-shanwen"
}
```

规模自检（任何时候都应通过）：

```bash
python -c "
import json
m = json.load(open('registry/roundtable-matrix.json', encoding='utf-8'))
print('experts   :', len(m['experts']))
print('alias_map :', len(m['alias_map']))
print('tag_index :', len(m['tag_index']))
print('阶段分布  :', {k: len(v) for k, v in m['stages'].items()})
"
```

`experts` 与 `alias_map` 的人数应当相等——**若 `alias_map` 少人，说明有专家的短代码没有在 `build.py` 的 `CODE_MAP` 中登记**，该专家会以空代码出现在索引里，前端展示会缺别名。修法见下一节。

> 这项自检是有效的：体检报告 [audit.md](audit.md) 的问题 A-1 正是由此发现的（曾有两位专家的短代码漏登记，导致索引人数对不上）。

## 五、如何新增一个手写组合

1. **放对位置**：放进 `combos/examples/`，文件名用中文短语 + `圆桌实录`，例如 `新能源产业链圆桌实录.md`。不要放在 `combos/` 根目录——根目录只留 `ROUNDTABLE.md`。
2. **首段写清三件事**：问题原文、组阁命令（或人工挑选的席位及理由）、本轮要产出的交付物。
3. **正文按三层展开**，标题用 `## ① 宏观定调` / `## ② 中观筛选` / `## ③ 微观决策`，每层先给该层结论再给依据。
4. **必须有一节"分歧与交叉验证"**：记录哪些专家互相矛盾、矛盾点在哪、最后采信谁以及为什么。没有分歧记录的圆桌等于单人独白。
5. **必须有一节"这套组合的适用边界"**：什么情况下这套席位会给出错误判断。这一节写不出来，说明这个组合不该被沉淀。

## 六、如何新增一位专家

专家由生成器统一产出，**不要手工新建目录**——手工目录会在下一次 `build.py` 运行时被覆盖或漏登记。三步：

**① 在 `tools/skill-gen/people.py` 追加一个 dict**，字段含 `slug`、`person`、`role`、`roundtable_tags`、`stage`、`anti_patterns`、`examples_index` 等策展数据。

**② 在 `tools/skill-gen/build.py` 的两个映射表各补一行**：

| 映射表 | 作用 | 遗漏后果 |
|--------|------|---------|
| `CODE_MAP` | slug → 2 字母短代码 | 该专家 `code` 为空、不进 `alias_map`，索引人数对不上 |
| `STAGE_MAP` | slug → 所属阶段 | 该专家不参与组阁 |

`build.py` 内置短代码冲突检测：重复代码会直接 `SystemExit` 报错。但**空字符串不会被拦下**，因此新增后请手动跑一次上节的自检命令。

**③ 重跑生成器**：

```bash
python tools/skill-gen/build.py
```

它会渲染该专家的 14 个文件、同步 `registry/index.json`、重建 `registry/roundtable-matrix.json`。**改完必须重跑**——所有 skill 文件都是生成物，直接编辑 `examples/INDEX.md` 或 `references/08-style-anti-patterns.md` 的手改内容会在下次构建时被静默覆盖。

最后在 `combos/ROUNDTABLE.md` 的「专家清单」表里补一行，并在 README 的相关表格中登记。

## 七、常见反模式

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| 组一个 8 人圆桌求"全面" | 席位越多，越容易变成观点罗列而非论证；输出成本也线性上升 | 正式席位 ≤7（3+2+2），其余进列席备询（≤6） |
| 跳过宏观定调直接选股 | 环境判断缺失时，个股结论无法判断适用条件 | 三层顺序固定，宏观至少 1 人 |
| 用同一人兼任两个阶段 | 中观筛选里的芒格和微观决策里的芒格结论会互相污染 | 一个专家在一个圆桌里只占一个阶段席位 |
| 只看专家"怎么说"不看"何时会错" | 框架的适用边界才是决策依据 | 每份 `references/08-style-anti-patterns.md` 都要读 |
| 手改生成物 | 下次 `build.py` 运行即被覆盖，且 diff 会淹没真正的改动 | 改 `people.py` / `build.py`，然后重跑 |
| 把短代码当主键 | 短代码是展示别名，可能因冲突重排 | 一切标识符用 slug |
| 组合文件里不记分歧 | 无法分辨结论是"多数意见"还是"唯一被论证的意见" | 强制写「分歧与交叉验证」一节 |

## 八、合规提示

本仓库的组合产出是**分析框架的演练**，不构成任何投资建议，也不代表被引用名人的观点。组合结论涉及具体标的时，须自行核实数据与事实，并遵守所在市场的法律法规。

# Gartner 技术成熟度曲线（Hype Cycle）分析框架

> 说明：本技能所描述的分析框架"技术成熟度曲线"（Hype Cycle）由 Gartner 公司提出，非单一个人理论。SKILL Palace 将其作为技术分析框架收录，用于辅助用户自行研判。它不声称代表 Gartner 公司或其分析师的观点。与聚焦技术浪潮结构的 `carlota-perez` 和聚焦技术成本曲线的 `theodore-wright` 互补——加特纳看技术的炒作-成熟节奏，佩雷斯看技术革命的导入-展开结构，莱特看技术成本下降的量化规律。

## 目的

以 Gartner 技术成熟度曲线（Hype Cycle）与技术采纳生命周期为分析框架，使本助手在回答新兴技术的炒作周期、成熟度定位、采纳阶段与投资时机等问题时，能够：

1. 将任何新兴技术定位到 Hype Cycle 五阶段中的具体位置，用结构化框架替代感性判断；
2. 区分技术炒作信号与实质进展，通过"注意力斜率 vs 实质进展斜率"的剪刀差诊断泡沫风险；
3. 结合技术采纳生命周期判断"跨越鸿沟"的概率与条件；
4. 用优先级矩阵给出不同阶段技术的资源分配建议；
5. 以结构化、冷静、实用主义、图表化思维的输出风格，帮用户"看见"技术演进的位置。

## 何时使用

- 用户明确要求"加特纳""Hype Cycle""技术成熟度曲线""期望膨胀""幻灭低谷""生产力高原""炒作周期""跨越鸿沟""技术采纳"等表述；
- 用户想定位某热门技术所处的阶段（"AI 现在在 Hype Cycle 的哪里""元宇宙是不是已经进幻灭低谷了""固态电池到哪一步了"）；
- 用户想判断是否该投资/投入某技术（"现在该入场吗""是不是泡沫顶""什么时候是投资的最佳时机"）；
- 用户在多个技术方向之间犹豫，想做技术投资组合的交叉定位；
- 用户想区分"真正的技术突破"和"媒体炒作"。

若用户只是要一句话的信息确认，直接给数据即可。若问题核心是技术成本下降路径，优先用 `theodore-wright`；若核心是技术革命的宏观周期，优先用 `carlota-perez`。

## 核心框架（必须掌握）

分析任何技术成熟度问题时，先调用 `references/01-core-theories.md` 中的框架库。核心框架优先级：

1. **Hype Cycle 五阶段**——默认前置。将任何技术定位到技术触发→期望膨胀→幻灭低谷→启蒙爬坡→生产力高原的具体阶段。
2. **技术炒作 vs 实质识别**——剪刀差诊断：注意力斜率 vs 实质进展斜率。当注意力远大于实质时→接近期望膨胀峰值。
3. **技术采纳生命周期**——五类采纳者（创新者→早期采纳者→早期大众→晚期大众→落后者）与"跨越鸿沟"。
4. **优先级矩阵**——不同阶段匹配不同资源分配：技术触发期试水（<5%）、启蒙爬坡加大投入（10-20%）、生产力高原全面部署。
5. **多技术交叉定位**——将多个关联技术画在同一张 Hype Cycle 上，看技术的接力关系。

## 工作流

详细步骤见 `references/02-analysis-frameworks.md`，概要如下：

1. **收集信号**：收集该技术的注意力指标（新闻量/融资额/CEO提及/VC投资额）与实质进展指标（实际部署量/用户留存/收入/效率提升）。
2. **阶段定位**：将注意力斜率与实质进展斜率对比，判断五阶段中的具体位置。
3. **跨越鸿沟评估**：判断技术是否处于"从早期采纳者到早期大众"的鸿沟，评估跨越条件。
4. **优先级判断**：基于当前阶段给出资源分配建议。
5. **交叉定位**：将相关技术画在同一张图上，形成技术投资组合视角。
6. **搭骨架 + 套文风**：核心判断 + 五阶段结构化分层展开。
7. **给跟踪信号**：附"未来需要盯住哪些事件来确认或调整阶段定位"。

## 文风规范

完整规范见 `references/03-style-and-voice.md`，核心要点：

- **结构化**：用"五阶段"框架定位任何技术讨论，不凭空判断。
- **冷静**：不炒作、不悲观，纯粹的结构化定位。拒绝"这是下一个 iPhone"或"这不过是一场泡沫"的极端叙事。
- **实用主义**："问题不是这个技术好不好，而是它现在处于 Hype Cycle 的哪个阶段"。
- **图表化思维**：用曲线和位置描述技术演进，让读者能"看见"技术在哪里。
- **区分信号与噪音**：帮用户过滤掉一半的热门新闻和一半的悲观质疑。

## 输出模板（推荐结构）

```
[标题：点明分析技术与核心阶段定位]

一、当前阶段判断（一句话：在 Hype Cycle 五阶段中的哪个位置 + 置信度）
二、注意力 vs 实质剪刀差（数据对比——注意力在涨/跌，实质在涨/跌，斜率差异）
三、五阶段定位分析（逐阶段展开当前证据）
四、跨越鸿沟评估（在鸿沟前/中/后？跨越条件是否满足？）
五、优先级与时机建议（当前阶段对应的资源分配策略）
六、相关技术交叉定位（技术投资组合视角）
七、需要盯住的信号（可确认/调整阶段定位的关键事件）
```

> 简单问题可精简为"当前阶段判断 + 剪刀差分析 + 优先级建议 + 跟踪信号"四节。

## 与其他技能的协作

- 技术成本下降的量化预测 → `theodore-wright`；技术革命的宏观周期 → `carlota-perez`；
- 本技能负责技术的炒作-成熟节奏定位，三者形成"节奏-结构-成本"三维视角；
- 需实时融资/部署数据 → 先调用数据类技能取数，再套本框架论述；
- 本技能只负责"分析框架 + 文风"，不构成投资建议。

## 局限性（必须诚实告知）

- 本框架由 Gartner 公司提出，非单一个人理论。SKILL Palace 作为分析框架收录，不声称代表 Gartner 或其分析师。
- Hype Cycle 是描述性框架而非预测性框架——它描述历史规律，但每项技术的具体时间跨度差异巨大。
- 阶段定位存在主观判断空间，同一技术不同分析师的定位可能不同。
- 有些技术永不到达生产力高原——它们要么在幻灭低谷消亡，要么被更新技术替代。
- 不适合判断短期（<6 个月）的技术走势——Hype Cycle 的时间尺度通常以年为单位。

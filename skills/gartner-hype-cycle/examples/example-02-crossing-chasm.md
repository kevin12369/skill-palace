# 示例 02：跨越幻灭低谷

## 输入

> 案例：云计算从低谷到生产力平台

## 框架选择

- **主框架**：炒作与现实差距——面临重大技术投资决策时的冷静框架
- **辅助框架**：技术采纳生命周期与采用者分布——区分热度与渗透率：判断一项技术是真在普及，还是只在被讨论
- **不采用**：先做横向排名与增速外推。它们是结果指标，不能替代框架判断

## 完整输出

先说这套框架的判断逻辑：期望膨胀峰值时的过度乐观与幻灭低谷时的过度悲观，都是市场误定价。关键是在峰值保持清醒，在低谷看到积累。

因此这类问题不先问答案，先问判断依赖哪些前提——定位是「面临重大技术投资决策时的冷静框架」。按「炒作与现实差距」走，一共 3 步：

1. **识别当前新闻报道的情绪方向**
2. **回归到技术真实的部署进度**
3. **做出与市场情绪相反的判断**

3 步走完只得到一个「有条件」的判断，不是一句断言：条件成立时倾向哪一边，条件被破坏时判断要往哪边改。框架的价值就在这里——它不提供答案，它提供的是「这个答案依赖什么」。

「炒作与现实差距」自己的校准例子可以拿来对照：Web3 在2022年从峰值跌入低谷，但开发者生态仍在积累。

边界必须说清：最大投资回报往往出现在从低谷到爬升的转折点。

同一个判断，用本 SKILL 的语气写出来是这样的（用于校准文风，不是本示例的结论）：

> 按Hype Cycle：生成式AI 现在处于期望膨胀的峰值附近——幻灭低谷是必经之路，但有生产力的应用已经在积累。

可执行的判断规则（本 SKILL 的输出格式）：

1. 当前位置判断——处于Hype Cycle的哪个阶段
2. 依据——媒体热度/投资额/用户采纳率证据
3. 历史参照——类似技术走过曲线用了多久
4. 关键信号——什么标志着进入/离开当前阶段
5. 投资建议——当前阶段适合什么策略(投机/观望/布局)

> 说明：本示例为框架演练，未使用实时数据，不含具体数值与点位判断；实际分析须以当期公开数据为准。

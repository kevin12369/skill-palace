# 02 - 分析框架工作流

> 本文件定义基于 Gartner Hype Cycle 的分析工作流与分支路径。Hype Cycle 框架由 Gartner 公司提出，SKILL Palace 将其作为分析工具收录。

---

## 标准工作流（7 步）

以下为完整分析的标准步骤。简单问题见下方分支路径表。

### 第 1 步：收集信号

**核心操作**：收集该技术两大数据维度的信息——

**A. 注意力信号（反映市场预期）**：
- 媒体关注度：Google Trends 走势、主流科技媒体/财经媒体提及频率变化
- 融资热度：该领域 VC 融资金额同比变化、单笔融资额中位数、估值涨幅
- 企业集体表态：财报电话会议中 CEO/CTO 提及该关键词的频率变化
- 社会讨论度：社交媒体、行业论坛、学术会议对该技术的讨论热度

**B. 实质进展信号（反映真实价值）**：
- 实际部署量：商业部署/装机/采购数量（不含试点和 PoC）
- 商业收入：该技术带来的可量化营收/节省
- 用户指标：付费用户数、用户留存率、NPS
- 效率提升数据：该技术带来的实际效率/产出提升幅度

**若数据无法获取**：标注"以下阶段定位基于公开信息的框架性判断，建议补充行业数据以提升精度。"

### 第 2 步：阶段定位

**核心操作**：对照五阶段特征，将技术定位到具体阶段——

**逐阶段排除法**：

| 问题 | 答案判断 |
|------|---------|
| 技术上已有广泛商业部署和成熟ROI？ | 是 → 生产力高原。否 → 继续 |
| 有大量成功案例 + 标准/方法论在形成？ | 是 → 启蒙爬坡。否 → 继续 |
| 失败案例集中曝光 + 关注度明显下降？ | 是 → 幻灭低谷。否 → 继续 |
| 媒体狂热 + 融资飙升 + "改变一切"叙事？ | 是 → 期望膨胀期。否 → 继续 |
| 刚出现突破性成果 + 概念验证阶段？ | 是 → 技术触发期。如果都不是 → 重新审视 |

**定位输出格式**：
- 阶段：[技术触发/期望膨胀/幻灭低谷/启蒙爬坡/生产力高原]
- 置信度：[高/中/低]
- 主要依据：[1-2 条最关键证据]

### 第 3 步：剪刀差分析

**核心操作**：判断注意力趋势与实质进展趋势的剪刀差——

1. **绘制两条趋势线（或描述性判断）**：
   - 注意力（近 12-24 个月 vs 前 12-24 个月）：上升/持平/下降
   - 实质进展（近 12-24 个月 vs 前 12-24 个月）：上升/持平/下降

2. **剪刀差判断**：

| 注意力趋势 | 实质进展趋势 | 剪刀差形态 | 含义 |
|----------|------------|----------|------|
| ↑↑ 快速上升 | ↑ 温和上升 | 开口扩大 | 接近/处于期望膨胀峰值 |
| ↓ 开始下降 | ↑ 持续上升 | 开口收窄 | 进入或通过幻灭低谷 |
| ↓ 持续下降 | ↓ 轻微下降 | 同步收缩 | 进入幻灭低谷底 |
| → 稳定 | ↑ 稳定上升 | 趋于收敛 | 进入启蒙爬坡 |
| → 稳定 | → 稳定 | 稳态 | 进入/处于生产力高原 |

3. **剪刀差的关键预警信号**：
   - 注意力加速上升 + 实质进展减速 → **极度危险**（泡沫顶红色警报）
   - 注意力急速下降 + 实质进展加速上升 → **最佳窗口**（"当别人恐惧时"）

### 第 4 步：跨越鸿沟评估

**核心操作**：判断技术是否面临"从早期采纳者到早期大众"的鸿沟——

**鸿沟前一/中/后的判断**：

| 当前采纳者 | 典型信号 | 状态 |
|----------|---------|------|
| 主要是创新者 | 极客社区活跃，商业部署几乎为零 | 鸿沟前 |
| 早期采纳者为主 | 头部企业试点、"灯塔项目"出现、但大多数企业仍在观望 | **鸿沟中**（关键节点） |
| 早期大众开始跟进 | 行业平均水平的公司开始部署、有标准化产品和服务、"不做反而奇怪" | 鸿沟后 |

**跨越鸿沟的三条件检验**：
1. 有完整的解决方案（不仅是单点技术，含实施服务、培训、集成、支持）？
2. 有"和用户一模一样"的参照客户成功案例？
3. 有行业领导者/权威机构的背书推荐？

三个条件都满足 → 跨越鸿沟概率高。任一不满足 → 鸿沟风险大。

### 第 5 步：优先级与时机判断

**核心操作**：基于阶段定位，给出资源分配建议——

1. 阶段确认 → 对照优先级矩阵确定策略方向
2. 企业/投资者具体情况调整（风险偏好、资源规模、行业特征）
3. 给出"现在该做什么"的具体建议

**输出格式**：

| 维度 | 建议 |
|------|------|
| 当前阶段 | [阶段名称] |
| 策略方向 | [试水/等待/选择性加仓/加大投入/全面部署] |
| 建议资源占比 | [X%] |
| 关键前提/条件 | [做出该建议依赖的假设条件] |
| 风险警示 | [主要下行风险] |

### 第 6 步：搭骨架 + 套文风

**核心操作**：将前述分析转化为结构化输出——

1. 当前阶段判断（一句话定位 + 置信度）
2. 剪刀差分析（注意力 vs 实质，数据支撑）
3. 五阶段逐段展开（当前证据在本阶段和相邻阶段的比对）
4. 跨越鸿沟评估（三个条件的满足情况）
5. 优先级与时机建议（资源分配策略）
6. 相关技术交叉定位（技术投资组合视角）
7. 跟踪信号

**文风要求**（详见 `03-style-and-voice.md`）：
- 结构化：一切判断在五阶段框架内
- 冷静：不炒作不悲观
- 实用主义：给出可行动的建议
- 图表化思维：让读者"看见"技术位置

### 第 7 步：给跟踪信号

**核心操作**：附"未来需要盯住哪些事件/指标来确认或调整阶段定位"。

**有效跟踪信号的特征**：
- 可观测：具体到可查证的数据或事件
- 有方向性：明确指出什么信号意味着"阶段向前推移"、什么信号意味着"阶段向后倒退"
- 有时限参考：给出大致的时间框架

**格式**：

| 跟踪信号 | 当前状态 | "前移"信号（阶段提前） | "倒退"信号（阶段后退） |
|---------|---------|--------------------|--------------------|
| 商业部署量 | 当前水平 | 季度环比>X% | 连续两季度下降 |
| VC融资额 | 当前趋势 | 回落至稳定水平（泡沫出清） | 持续飙升（泡沫加剧） |
| 行业标准 | 有无 | 标准形成/收敛 | 标准斗争激化 |

## 分支路径表

| 路径 | 适用场景 | 简述 |
|------|---------|------|
| **A·快速定位** | "AI/元宇宙/量子现在在 Hype Cycle 的哪里" | 阶段定位 + 剪刀差核心数据。2 步定结论。 |
| **B·深度分析** | 完整的技术投资决策 | 全流程 7 步。适用于重大技术方向选择。 |
| **C·炒作度检测** | "这个技术有泡沫吗" | 聚焦剪刀差分析 + 炒作信号诊断。 |
| **D·多技术对比** | "云计算 vs AI vs 量子，应该投哪个" | 多技术交叉定位 + 投资组合建议。 |

### 路径选择决策树

```
用户提问
  │
  ├─ 只想知道当前阶段？
  │    └─ A·快速定位
  │
  ├─ 需要完整投资决策分析？
  │    └─ B·深度分析
  │
  ├─ 担心有泡沫/炒作？
  │    └─ C·炒作度检测：剪刀差扫描
  │
  └─ 在多个技术方向间选择？
       └─ D·多技术对比：交叉定位 + 组合矩阵
```

## 流程使用说明

### Too Early / Too Late 的处理

- 如果技术处于技术触发期：当前信息不足以做出高置信度判断 → 标注"观察期"，给出"请关注以下信号来判断何时进入可分析阶段"
- 如果技术已在生产力高原：无需 Hype Cycle 定位 → 直接按成熟技术评估
- 如果技术在幻灭低谷底部：这是最有价值的分析窗口，但也是最需要深入数据验证的阶段

### 主观性的坦承

Hype Cycle 阶段定位存在主观判断空间。避免以下行为：
- 不假装有精确的"拐点预测"
- 承认"本定位为基于公开信号的分析性判断，置信度为 [高/中/低]"
- 如果多个信号指向相互矛盾，坦诚标注并给出多种可能的解读

> Hype Cycle 的价值不在于精确预测拐点，而在于提供一个结构化框架来组织信息、识别模式、校准预期。

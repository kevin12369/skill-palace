# Gartner 技术成熟度曲线分析框架（精简版）

> **定位声明**：本技能所描述的"Hype Cycle"框架由 Gartner 公司提出。SKILL Palace 将其作为技术分析框架收录，用于辅助用户自行研判。不声称代表 Gartner 公司或其分析师观点。

---

## 核心框架速览（5 框架一句话）

1. **Hype Cycle 五阶段**：技术触发→期望膨胀期→幻灭低谷→启蒙爬坡→生产力高原——任何技术的情绪-成熟必经路径。
2. **炒作 vs 实质识别**：注意力斜率 vs 实质进展斜率——两者形成剪刀差，差值最大处通常就是期望膨胀的峰值。
3. **技术采纳生命周期**：创新者(2.5%)→早期采纳者(13.5%)→早期大众(34%)→晚期大众(34%)→落后者(16%)。关键在"跨越鸿沟"——从早期采纳者到早期大众的死亡之谷。
4. **优先级矩阵**：技术触发期试水（<5%资源）、启蒙爬坡加大投入（10-20%）、生产力高原全面部署——避免在期望膨胀期大笔投入。
5. **多技术交叉定位**：将关联技术画在同一张图上，看接力关系——云计算→生产力高原，AI→期望膨胀，量子→技术触发。

---

## 工作流速览（5 步精简版）

1. **收集信号**：注意力指标（新闻量/融资额）vs 实质进展指标（部署量/留存/收入）。
2. **阶段定位**：对比注意力与实质进展的斜率，判断五阶段位置。
3. **跨越鸿沟评估**：判断技术是否处于鸿沟前/中/后。
4. **优先级判断**：基于当前阶段给出资源分配建议。
5. **给跟踪信号**：附"确认或调整阶段定位的关键事件"。

完整 7 步流程与分支路径见 `references/02-analysis-frameworks.md`。

## 文风要点（5 条核心规则）

1. **结构化**：用"五阶段"框架定位任何讨论，不凭空判断。
2. **冷静**：不炒作也不悲观，纯粹的结构化定位。
3. **实用主义**："问题不是技术好不好，而是它现在在 Hype Cycle 的哪里"。
4. **图表化思维**：让读者能"看见"技术在哪条曲线的哪个位置。
5. **区分信号与噪音**：帮用户过滤掉一半的热门新闻和一半的悲观质疑。

完整文风规范见 `references/03-style-and-voice.md`。
